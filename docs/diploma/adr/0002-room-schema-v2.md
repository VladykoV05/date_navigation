# ADR-0002: Схема комнаты v2

**Статус:** Proposed
**Дата:** 2026-10-27

## Контекст
Текущая схема `rooms/{id}` жёстко бинарная: `creatorUid`/`partnerUid`,
`point1`/`point2`, `creator*`/`partner*`. Это устраивает приватную комнату, но
не поддерживает открытые сессии, чат, несколько участников и кастомные форматы.
Rules также ролевые и не масштабируются.

## Варианты
### A. Оставить v1 и добавить отдельную коллекцию `openRooms`
- Плюс: не трогаем приватный сценарий.
- Минус: две модели, дублирование логики, чат/форматы всё равно нужны в обеих.

### B. Расширить v1 полями `type/capacity/participants[]` без подколлекций
- Плюс: минимум изменений.
- Минус: конфликты записи за один документ, сложные rules на map-поля,
  риск перезаписи чужих точек.

### C. Схема v2 с participant-подколлекцией (выбрана)
- Плюс: свои права на пользователя, меньше конфликтов, чистые rules,
  естественное место для чата/read/custom formats.
- Минус: больше чтений, нужен адаптер и миграция.

## Решение
Вариант C. `rooms/{id}` — метаданные и согласованное состояние;
`rooms/{id}/participants/{uid}` — личные поля; `messages`, `reads`,
`customFormats` — подколлекции. Приватная комната = `type=private, capacity=2`
и тот же invite-механизм. Открытая = `type=open, visibility=public`, capacity N.
Комната может содержать `event` — снимок события TicketPro или ручной карточки
(title, startsAt, venue, lat/lon, sourceUrl). Participant содержит `liveLocation`
(текущая позиция на время sharing) отдельно от `point` (снимок для планирования).

Совместимость: адаптер чтения v1 → v2; новый код пишет только v2; миграционный
скрипт идемпотентный, с dry-run. `creatorUid/partnerUid` остаются derived на
переходный период.

## Последствия
- Нужно обновить mapper, reducer, state, rules, индексы, тесты.
- Приватный сценарий должен остаться рабочим (регрессия).
- Появляется место для чата и кастомных форматов.
- Чтение комнаты становится дороже (1 + N документов); для малых N приемлемо.

## Проверка
- Contract/emulator-тесты: join, capacity, чужие поля, чат.
- Ручной smoke: приватная и открытая комнаты на 2–3 устройствах.
- Метрика: число чтений на открытие комнаты; сравнение с v1.
