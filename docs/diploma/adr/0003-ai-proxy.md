# ADR-0003: AI-консьерж через внешний прокси

**Статус:** Accepted
**Дата:** 2026-10-27
**Обновлено:** 2026-11-04 — выбран внешний прокси (Cloud Functions недоступны
из-за billing в Беларуси)

## Контекст
Нужен AI-консьерж подбора (формат/место/следующий шаг) с объяснением. Нельзя
хранить ключ LLM в мобильном клиенте: его можно извлечь, а стоимость запросов
не ограничить. Модель должна видеть только контекст комнаты и выдачу мест,
не выдумывать места и деградировать при ошибке.

Дополнительно: Беларуси нет в списке стран Cloud Billing, поэтому Blaze и
Cloud Functions недоступны. Нужен серверный слой вне Firebase.

## Варианты
### A. Прямой вызов LLM из Flutter
- Плюс: быстро.
- Минус: ключ в клиенте, нет rate limit, невозможно безопасно деплоить.

### B. Cloud Functions (Blaze)
- Плюс: интеграция с Auth/Firestore, триггеры.
- Минус: нужен billing account, недоступный для Беларуси.

### C. Внешний прокси (выбран)
- Плюс: работает без Blaze, ключ на сервере, можно разместить на доступном
  хостинге, подходит и для AI, и для push.
- Минус: отдельный деплой, секреты, мониторинг.

## Решение
Выбран **внешний прокси** — Node.js/TypeScript сервис (Fastify).
Клиент вызывает `POST /aiSuggest` с контекстом; прокси:
1. проверяет Firebase ID token (Admin SDK);
2. проверяет участие в комнате по `rooms/{roomId}/participants/{uid}`;
3. валидирует вход (zod/JSON schema, лимиты);
4. применяет rate limit по uid/room;
5. вызывает LLM с таймаутом;
6. валидирует JSON и **проверяет, что placeId есть в переданной выдаче**;
7. возвращает 3 варианта с причинами;
8. логирует метрики без ПДн.
При ошибке клиент использует детерминированный `DateAssistantService`.

Для push: тот же сервис (или отдельный listener) с Firebase Admin SDK слушает
`rooms/{roomId}/messages` и отправляет FCM участникам. Если listener не
поднимаем — остаются local notifications, push помечается как stretch.

## Хостинг
Сервера нет, поэтому основной стенд — локальный Mac:
- Fastify + Ollama локально; Cloudflare Tunnel даёт HTTPS-URL для телефонов.
- Push-listener — в том же процессе; Mac включён на время демо.
- Production-like: позже Docker на университетском сервере/VPS или Render/Fly.
- Cloudflare Workers — только если понадобится публичный AI-эндпоинт без Mac;
  потребует Hono/свой auth и не подходит для push-listener.

## Безопасность
- `LLM_API_KEY` и service account — только в env/secret store прокси.
- `DEV_SKIP_AUTH=true` только локально; в деплое обязательно `false`.
- CORS allowlist, лимит размера тела, таймауты.
- Валидация выхода: только placeId из контекста, reason без ПДн.
- Логи без текста сообщений и координат.

## Последствия
- Нет зависимости от Blaze; Firebase остаётся на Spark.
- Нужен отдельный деплой и мониторинг прокси.
- Push может быть local-only, если listener не успеваем.
- Cloud Functions каркас (`functions/healthCheck`) остаётся как резерв на случай
  появления университетского billing account.

## Проверка
- `GET /health` → 200 (проверено локально 2026-11-04).
- `POST /aiSuggest` с невалидным телом → 400 (проверено).
- `POST /aiSuggest` с mock → 3 варианта из выдачи.
- Без токена → 401; чужой room → 403/404.
- placeId вне выдачи → отбраковка/fallback.
- Ключ отсутствует в клиентском бандле.
