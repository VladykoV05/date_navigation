# ADR-0007: Push-уведомления на iOS не реализуются

**Статус:** Accepted
**Дата:** 2026-11-05

## Контекст
R3 включает уведомления о новых сообщениях. Чтобы они приходили при свёрнутом
приложении, нужен push-канал. На iOS любой push проходит через APNs. Для
доставки через FCM/APNs нужен APNs-ключ или сертификат, а также entitlement
«Push Notifications».

Проверено:
- entitlement «Push Notifications» доступен в полной подписке Apple Developer Program;
  в документации Apple таблица возможностей для бесплатного аккаунта не
  подтверждает наличие push (явного запрета в источниках не найдено);
- проверка в Xcode (добавление capability на Personal Team) не проводилась;
- локальные уведомления (`flutter_local_notifications`) работают только пока
  приложение активно или сразу после сворачивания: iOS приостанавливает
  подписку Firestore в фоне.

Альтернативы, которые рассматривались:
- ntfy (бесплатно, доставка через APNs сервера ntfy.sh). Требует второго приложения
  у получателя, публичных тем и отправки с прокси, который работает постоянно;
  для сообщений внутри приложения это плохо ложится на модель.
- Web push через PWA (iOS 16.4+). Отдельная сборка, не нативный Flutter.
- Android-only push через FCM. Бесплатно, но не закрывает iOS-устройства демо.

## Решение
Push-уведомления на iOS в проекте **не реализуются**. Для уведомлений о сообщениях
используются локальные уведомления и синхронизация при возврате в приложение.
Отсутствие push на iOS фиксируется как ограничение.

## Последствия
- Уведомления работают при открытом приложении и сразу после сворачивания.
- Пропущенные сообщения видны при возврате (бейдж, загрузка из Firestore).
- В разделе ограничений диплома описываются причины и альтернативы.
- Если появится Apple Developer Program или Android-устройство, push можно
  добавить отдельным блоком. Пересмотр решения — в этом ADR, новым ADR.
- Тестовые сценарии уведомлений в фоне помечаются как «не применимо на iOS».
