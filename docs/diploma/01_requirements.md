# Требования

## 1. Функциональные требования

### FR-1. Локация и глобальный поиск
- FR-1.1. Приложение получает текущую геопозицию устройства по запросу.
- FR-1.2. Пользователь может использовать текущую позицию как «мою точку».
- FR-1.3. При отказе в разрешении доступен ручной ввод адреса.
- FR-1.4. Геокодинг работает без жёсткой привязки к Минску и `countrycodes=by`.
- FR-1.5. Пользователь может выбрать страну/регион поиска; выбор сохраняется.
- FR-1.6. Ошибки геокодинга (timeout, 429, пустой результат) показываются понятно.
- FR-1.7. Результаты геокодинга кэшируются с учётом локали и региона.

### FR-2. Открытые сессии и события
- FR-2.1. Пользователь создаёт приватную (invite, 2 участника) или открытую сессию.
- FR-2.2. Открытая сессия имеет название, формат, capacity, срок жизни.
- FR-2.3. Открытые сессии видны в списке (страна/город, формат, событие, участники, расстояние).
- FR-2.4. Пользователь вступает в открытую сессию, если есть место и она активна.
- FR-2.5. При заполнении capacity вступление отклоняется с понятной ошибкой.
- FR-2.6. Приватная комната сохраняет текущий invite-сценарий и `roomFull`.
- FR-2.7. Хост может завершить сессию; участник может выйти.
- FR-2.8. Точные личные точки не показываются в списке открытых сессий.

### FR-3. Чат и уведомления
- FR-3.1. В приватной и открытой сессии есть текстовый чат.
- FR-3.2. Сообщения доставляются в реальном времени и сохраняются в истории.
- FR-3.3. История подгружается страницами; старые сообщения не теряются.
- FR-3.4. Отправка оптимистична; повтор/ретрай не создаёт дубликат.
- FR-3.5. Системные сообщения фиксируют join, смену формата, выбор места.
- FR-3.6. Есть unread-индикатор и локальное уведомление о новом сообщении.
- FR-3.7. Push-уведомление (stretch) приходит при закрытом приложении.
- FR-3.8. Переход по уведомлению открывает нужную комнату/чат.

### FR-4. Форматы
- FR-4.1. Список встроенных форматов расширен (не менее 6).
- FR-4.2. Внутри формата есть набор типов заведений/chip'ов.
- FR-4.3. Пользователь создаёт кастомный формат: название, иконка, набор chip'ов.
- FR-4.4. Кастомный формат сохраняется в личной библиотеке и применяется в комнате.
- FR-4.5. Участники видят кастомный формат в отдельном блоке UI.
- FR-4.6. Кастомный формат участвует в фильтрации и ранжировании мест.
- FR-4.7. Некорректный/опасный селектор отклоняется с ошибкой.

### FR-5. «Куда дальше» и маршрут
- FR-5.1. После финального выбора заведения приложение предлагает следующий шаг.
- FR-5.2. Предложения учитывают расстояние/время, формат и разнообразие категорий.
- FR-5.3. Пользователь добавляет следующий шаг в сценарий встречи.
- FR-5.4. Маршрут строится в приложении: геометрия, расстояние, ETA.
- FR-5.5. Маршрут показывается для каждого участника до места и между шагами.
- FR-5.6. При недоступности OSRM показывается деградированный режим, не пустой экран.
- FR-5.7. Внешняя навигация (Яндекс/Google Maps) остаётся как fallback.

### FR-6. AI-консьерж
- FR-6.1. Консьерж доступен в комнате после появления контекста (точки/формат/места).
- FR-6.2. Он предлагает 3 варианта: формат, место или следующий шаг.
- FR-6.3. Каждый вариант содержит объяснение (почему подходит).
- FR-6.4. Консьерж не предлагает места вне выдачи приложения.
- FR-6.5. При ошибке/таймауте — fallback на детерминированные сценарии.
- FR-6.6. Ключ LLM не хранится в клиенте.
- FR-6.7. Есть ограничение частоты и стоимости запросов.

### FR-7. События (TicketPro)
- FR-7.1. Пользователь ищет события TicketPro по категории/городу.
- FR-7.2. Пользователь импортирует событие по ссылке TicketPro.
- FR-7.3. Карточка события показывает название, дату, площадку, адрес, цену, фото.
- FR-7.4. Координаты площадки берутся из JSON-LD страницы площадки.
- FR-7.5. Из события создаётся открытая сессия; событие сохраняется снимком.
- FR-7.6. Если TicketPro недоступен/не распознан — ручная карточка события.
- FR-7.7. Данные показываются с атрибуцией «Данные: TicketPro» и ссылкой.
- FR-7.8. Запросы к TicketPro кэшируются и ограничены по частоте.

### FR-8. Live-геолокация (stretch после R2)
- FR-8.1. Участник включает sharing на 60 минут.
- FR-8.2. Точка обновляется, даже если приложение свёрнуто.
- FR-8.3. Напарник видит live-маркер, точность и «обновлено N сек назад».
- FR-8.4. Авто-стоп: час, финальное место, выход из комнаты.
- FR-8.5. `point` (план) и `liveLocation` (сейчас) — разные поля/маркеры.
- FR-8.6. Центр встречи не пересчитывается автоматически; только по кнопке.
- FR-8.7. Live-геолокация только в приватных комнатах.
- FR-8.8. При отказе в background-разрешении — fallback на foreground/снимок.
- FR-8.9. История не хранится; только последняя точка.

## 2. Нефункциональные требования
- NFR-1. **Производительность:** геокодинг p95 < 3 с при нормальной сети; сообщение < 2 с.
- NFR-2. **Надёжность:** нет потери сообщений при кратком offline; повтор не дублирует.
- NFR-3. **Безопасность:** доступ к комнате/чату только участникам; rules покрыты тестами.
- NFR-4. **Приватность:** точные точки не публикуются; ключи и токены не в репозитории.
- NFR-5. **Масштабируемость:** открытая сессия выдерживает N участников (N задаётся).
- NFR-6. **Совместимость:** Android и iOS; ru/en UI; светлая/тёмная тема.
- NFR-7. **Доступность:** text scale, контраст, semantics для ключевых действий.
- NFR-8. **Сопровождаемость:** слои, тесты, ADR, traceability.
- NFR-9. **Деградация:** при 429/timeout внешних API — кэш/сообщение/fallback.
- NFR-10. **Стоимость:** AI-запросы лимитированы; push не спамит.

## 3. User stories (ключевые)
- Как организатор, я хочу создать открытую сессию, чтобы найти компанию на встречу.
- Как организатор, я хочу взять событие TicketPro и создать сессию «идём вместе».
- Как участник, я хочу видеть открытые сессии и события рядом, чтобы присоединиться.
- Как участник, я хочу обсудить детали в чате, не уходя в мессенджер.
- Как пользователь, я хочу использовать своё местоположение, а не вводить адрес.
- Как пользователь, я хочу искать место в другой стране, а не только в Минске.
- Как пользователь, я хочу создать свой формат встречи, если стандартных мало.
- Как пользователь, я хочу после ужина увидеть, куда можно пойти дальше.
- Как пользователь, я хочу, чтобы приложение предложило вариант и объяснило почему.
- Как участник, я хочу на час делиться геопозицией, чтобы напарник видел, где я.

## 4. Ограничения
- Публичные Nominatim/Overpass/OSRM: лимиты, отсутствие SLA, OSRM demo — driving.
- TicketPro — не официальный API; JSON-LD может измениться, нужен fallback.
- Live-геолокация требует background permissions и может быть ограничена ОС/магазином.
- Firebase Spark не даёт Cloud Functions; push/AI требуют Blaze или внешний прокси.
- iOS/Android permissions и фоновые уведомления зависят от ОС.
- В приватной комнате остаётся 2 участника; multi-user — только открытые сессии.
- UI остаётся ru/en; «разные страны» = глобальный поиск, не новые языки.
