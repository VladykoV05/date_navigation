## Решения
- Push-уведомления на iOS в проекте не реализуются. Причина: APNs-канал
  требует платной подписки Apple Developer Program, на бесплатном аккаунте
  push-entitlement недоступен (проверка через Xcode не проведена). Решение
  зафиксировано в ADR-0007.
- Уведомления о сообщениях работают в открытом приложении и сразу после сворачивания;
  пропущенное догружается при возврате (Firestore-синхронизация).
- Для демо используется release-сборка на устройстве, для разработки — `flutter run`
  с подключением по кабелю.
- Текущий приоритет: работа фич end-to-end (вход, точка, выход, завершение, чат,
  профиль собеседника), а не идеальная полировка. Полировка — R7.

## Ключевые наблюдения
- **Крэш `LateInitializationError`.** `DateNavigationController` держится в памяти
  (keepAlive). `ref.invalidate` из `main.dart` (выход из аккаунта) и из меню аккаунта
  заставляет Riverpod вызвать `build()` повторно на том же экземпляре. Поля,
  инициализируемые как `late final`, падают на втором вызове. Исправлено в `477f21d`.
- **Выход из комнаты локальный.** `RoomSessionController.leaveRoom()` отменяет
  подписку и сбрасывает state, документ участника в Firestore не меняется. Второй
  участник продолжает видеть двоих, место в открытой сессии не освобождается.
  Правила запрещают удаление документа участника (`allow delete: if false`).
- **Сценарий завершения не подключён к UI.** `CompleteSession` есть в DI, но
  не вызывается из интерфейса; комната закрывается только по истечении времени.
- **Чат пишется в завершённую и истёкшую комнату.** Правила проверяют только
  членство в `participants`, но не `sessionStatus`.
- **Тап по локальному уведомлению не обрабатывается.** Payload `room:$roomId`
  формируется, обработчика `onDidReceiveNotificationResponse` нет.
- **Лимит событий.** Приложение запрашивает 10, прокси обрезает `limit` до 10
  (`Math.min(..., 10)`). Это ограничение нашего кода, а не TicketPro.
- **Список событий зависит от `EVENTS_PROXY_URL`.** Без `--dart-define` адрес пустой,
  и диалог показывает «события недоступны». Симулятор может использовать
  `127.0.0.1`, телефон — IP Mac в той же Wi-Fi сети.
- **Точка участника в открытой сессии не видна.** Список открытых сессий показывает
  только название события и счётчик (`1 из 4`). Точки участников рисуются только
  на карте внутри комнаты; если и там их нет, это баг записи точки (не проверено).
- **Вход Google.** Изменения в AppDelegate и `AuthSignInService` не проверены
  на устройстве.

## Открытые вопросы
- Точка участника: записывается ли она после ввода адреса и где именно пропадает.
- Выход участника: как в правилах разрешить удаление (или статус «вышел») без
  открытия лишних прав.
- Завершение сессии: кто может завершить (хост / любой участник) и что происходит
  с чатом.
- Чтение «прочитано»: показывать «кем» для открытой сессии (аватары и список имён).
- Публичный профиль собеседника: какие поля видны участникам одной комнаты
  (имя, фото из Google `photoURL`, точка, выбранный формат). Текущее правило
  `users/{uid}` разрешает чтение только самому пользователю.
- Фото на маркере: использовать `photoURL` из Google-аккаунта, загрузка своих
  фото (Firebase Storage) требует Blaze и откладывается.
