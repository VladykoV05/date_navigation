## Решения
- Название продукта: **Sbor** (нейтральное, про встречи и события).
- Делаем все 6 блоков; срок — лето 2027 (предварительно конец июня).
- Код-фриз 2027-05-25, заморозка текста 2027-06-08 (R2 +2 недели на события).
- Scope согласован с научруком; 2–3 устройства есть.
- Backend: выбран **внешний прокси** (Fastify), потому что Cloud Functions
  требуют Blaze, а Беларуси нет в списке стран Cloud Billing. Firebase — Spark.
- Сервера нет: основной стенд — локальный Mac + Cloudflare Tunnel; production-like
  позже (Docker на университетском сервере/VPS).
- AI: локальная Ollama (llama3.1:8b / qwen2.5:7b), провайдер за интерфейсом.
  Установка и модель отложены до R6; сейчас достаточно mock-режима.
- События: TicketPro JSON-LD — основной источник, ручная карточка — fallback;
  Ticketmaster — второй провайдер на будущее. R2 +2 недели.
- Live-геолокация: stretch после R2; отдельный маркер от точки планирования;
  центр пересчитывается только по кнопке; ADR-0006.
- Модель центра для N: ADR-0004 (Proposed), гибрид «середина маршрута для 2 +
  min(max duration) для N + fallback на медиану».

## Ключевые наблюдения
- Текущая «равноудалённая точка» — точка на маршруте по половине времени в пути,
  а не геометрический центр/изохрона. Для открытых сессий это ограничение.
- Главный доменный ограничитель — бинарная модель комнаты (2 участника).
- Приватность точек и сообщений — требование домена, не «полировка».
- «Куда дальше» — отдельный сценарий, а не побочный эффект маршрута.
