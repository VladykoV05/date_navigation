# Анализ существующих решений и технологий

Предметная область, акторы, процессы и бизнес-правила — в
`02_domain_analysis.md`. Здесь — аналоги, технологии и выбор стека.

## 1. Аналоги и их границы
| Класс | Примеры | Что закрывают | Чего не хватает |
|---|---|---|---|
| Мессенджеры | Telegram, WhatsApp | Чат, группы, приглашения | Нет подбора места, расстояний, формата |
| Карты | Google Maps, Яндекс Карты, 2ГИС | Поиск мест, маршруты, ETA | Нет совместного решения и голосования |
| События | Meetup, Timepad | Открытые события, запись | Нет «равноудалённой точки» и парного сценария |
| Планирование встреч | Doodle, When2Meet | Согласование времени | Нет места, маршрута, чата |
| Свидания/встречи | Partiful, HowAboutWe | Идеи и приглашения | Слабая геометрия, нет открытых сессий |

Вывод: ниша — не «ещё один мессенджер» и не «ещё одна карта», а сценарий
«согласовать место и формат с учётом точек участников». Это ядро продукта.

## 2. Сравнение технологий

### 2.1. Backend
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Firebase Firestore | Realtime listeners, offline, Auth, правила, быстрый старт | Нет гео-запросов «из коробки», цена за чтения, vendor lock | **Выбран** (уже в проекте) |
| Firebase Realtime DB | Простая синхронизация | Слабее запросы/правила, меньше структуры | Нет |
| Supabase | SQL, realtime, open source | Нужен свой хостинг/миграции, другой стек | Нет |
| Свой backend | Полный контроль, гео-индексы | Время на инфраструктуру, auth, push | Нет для диплома |

### 2.2. Состояние
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Riverpod | Компилируемый DI, тесты, уже в проекте | Кривая обучения | **Выбран** |
| BLoC | Явные события/состояния | Больше бойлерплейта | Нет |
| Provider | Просто | Слабее для сложного графа | Нет |

### 2.3. Карты и геоданные
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| flutter_map + OSM | Бесплатно, гибко, уже в проекте | Нужен tile-провайдер, attribution | **Выбран** |
| Google Maps SDK | Богатый функционал | Ключ, цена, зависимость | Нет |
| Mapbox | Хороший UX | Цена/ключ | Нет |

### 2.4. Геокодинг
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Nominatim | OSM, бесплатно, предсказуемо | Лимиты, policy, качество | **Основной** |
| Photon | Хорош для не-латинских/экзонимов | Свой инстанс/лимиты | **Fallback** |
| Google Geocoding | Качество | Цена, ключ | Нет |

### 2.5. Маршруты
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| OSRM demo | Бесплатно, polyline, ETA | Только driving, без SLA | **Выбран для MVP** |
| Свой OSRM | Контроль профилей | Хостинг/данные | Stretch |
| Google Directions | Профили, transit | Цена, ключ | Нет |

### 2.6. AI
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| LLM через серверный прокси | Ключ не в клиенте, контроль | Нужен backend, цена | **Выбран** |
| On-device модель | Приватность, offline | Размер, качество, сложность | Нет |
| Без LLM (эвристики) | Дёшево, предсказуемо | Нет объяснений/гибкости | Fallback |

### 2.7. Push
| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| FCM + Cloud Functions | Стандарт, триггеры | Blaze, настройка APNs | Stretch/цель |
| Local notifications | Без backend | Только foreground/по расписанию | **MVP** |
| Сторонний сервис | Проще | Зависимость, цена | Нет |

## 3. Ограничения внешних сервисов
- Nominatim: User-Agent, не более 1 запроса/с, кэш, запрет тяжёлого bulk.
- Overpass: сложные запросы дорогие; нужен таймаут и fallback.
- OSRM demo: только driving, без гарантий; для пеших/транспортных сценариев — ограничение.
- Firestore: нет гео-запросов; нужен geohash/bounding box или клиентская фильтрация.
- FCM: требует проекта Firebase и настройки APNs для iOS.

## 4. Выводы для проекта
1. Оставляем Firebase + Riverpod + flutter_map: минимум новых зависимостей.
2. Геокодинг делаем глобальным, с кэшем и деградацией.
3. Открытые сессии требуют схемы v2 и geo-индекса (geohash или city/country + клиентский фильтр).
4. Маршрут в приложении строим на OSRM, внешние карты — fallback.
5. AI — только через серверный прокси, с fallback на эвристики.
6. Push — local в MVP, FCM — при наличии backend.
